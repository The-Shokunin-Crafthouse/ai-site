Overview :: Workflow :: Studio Brain :: Tools

Thirteen steps from brief to ship.

Every step says exactly which tool, which prompt, and which approval gate. I do five of them. AI does the rest.

0 of 13 explored

  1. The brief is direction, not detail. The Planner expands it into a full product spec in the next step. I keep this short on purpose because length here makes the spec rigid downstream.

    What I write: what the site is for, who the visitor is, what they need to do or understand, what makes it different from every other site in the category.

  2. The Planner runs in the Shokunin Crafthouse project on Claude.ai. studio-memory.md is already in the project knowledge, so it reads our identity and design principles before expanding the brief.

    What it returns: project overview, complete deliverables list, design direction tied to the seven Shokunin principles, technical stack, three to six sprints, and specific success criteria per sprint.

    Approval gate one — Concept. I read the spec carefully and edit anything I disagree with before moving on.

  3. Figma MCP cannot create files. This step is always manual. I name the file, set up the four pages, and grab the file URL for the scaffold prompt.

    The Sandbox rule: Sandbox is creative workspace, Production is canonical. Promotion is always manual. Claude reads from both but writes to neither.

  4. Claude Code clones the workspace template, creates a private GitHub repo under the studio org, populates WORKSPACE.md with project identity, wires in the Figma file URL, and confirms all four Figma pages exist via MCP.

    It also adds a Playwright preview script that captures screenshots at 360, 768, 1024, and 1440 so every PR carries a snapshot record. Optional /goal drives this through to a green build without per-turn prompting.

  5. Push to main triggers an rsync to Hostinger production. Every PR opens triggers a preview build at /_previews/[pr-number]/ with a sticky comment dropping the live URL into the PR. Close the PR and the cleanup workflow tears the directory down.

    Claude Code prints the predicted preview URL directly in chat and runs gh run watch to confirm the deploy succeeded. No GitHub round-trip to find a URL.

  6. Claude Design runs on Opus 4.7 with its own independent weekly limit that does not touch the Max pool. I treat it as a free creative resource for exploration before committing anything to Figma.

    The pattern is two opposing directions: my instinct, then its opposite. The contrast forces a decision about point of view. Output saves to stages/02-design/claude-design/.

  7. I build color styles, the type scale, the spacing scale, and base components on the Sandbox page. Type is solved before anything else because changing typefaces later is a redesign.

    Then Claude Code reads the Figma file via MCP and writes _config/design-system/token-map.md. That file becomes the source of truth — no color, font, or spacing value gets used in code unless it lives there.

    Approval gate two — Design. Token map approved before any sprint starts.

  8. One section, designed completely, before the next one starts. Every breakpoint is drawn, never assumed. Every interactive element has all five states: default, hover, focus, active, disabled.

    Motion decisions are written into decisions/decisions.md, not just prototyped. Dark mode is either fully designed or formally deferred — the decision is logged.

  9. The Generator reads WORKSPACE.md, studio-memory.md, and token-map.md, pulls the Sandbox frames via Figma MCP, and proposes a sprint contract before writing a line of code. I approve the contract in writing first.

    Implementation is mobile-first across all four breakpoints. Asset paths must work both at root and at /_previews/[N]/. The PR opens with four snapshot screenshots embedded and a sticky comment carrying the live preview URL.

    Dispatched via Agent View as a background session, so the build runs without my attention. Optional /goal drives it through to a ready-to-review PR after the contract is approved.

  10. A fresh Claude Code session, deliberately uncontaminated by the build context. It reads the snapshots, fetches the live preview to confirm structural integrity, then audits the code for token discipline and accessibility patterns.

    Grades against Originality, Design Quality, Craft, Functionality. Craft and Functionality are required passes — sprints cannot ship with failures there. Skeptical by design: uncertainty equals fail.

    Never put a /goal on this session. The Evaluator is single-pass by design; a goal would loop it on itself and defeat the audit.

  11. Final desktop and phone review on the preview URL. Click Merge. The production deploy workflow rsyncs to Hostinger in seconds; the cleanup workflow tears down the preview directory in parallel.

    Then I promote the approved frames from the Figma Sandbox page to the Production page. Always manual. Always me.

    Approval gate three — Development. Sprint passes only after preview review, evaluator PASS, and final visual check.

  12. One section at a time. I do not design everything before building anything. The loop produces fast feedback: each shipped section informs the next, and the studio memory grows project-by-project rather than at the end.

  13. After delivery, Cowork appends to studio-memory.md: design approaches that worked, code patterns that became standing standards, mistakes to avoid next time, and any new aesthetic preferences that emerged.

    Approval gate four — Delivery. Memory updated, decisions logged, the project closes. The next project starts with that knowledge already loaded.

4A Studio memory ▾

One file, read at the start of every Claude Code session: studio-memory.md. It holds the studio identity, the seven design principles, the four design quality criteria, the technology stack, the code standards, the approval gates, the creative defaults, and a running log of accumulated learnings.

It is not a document for humans. It is dense, directive, and written as instructions Claude reads to do its job. The file is short on purpose. Length is friction.

Three real entries from §8 Accumulated Learnings:

  • Next.js trailingSlash: true needs skipTrailingSlashRedirect: true for POST routes. 2026-05-09

    POST requests get 308-redirected and never reach the handler. Stripe webhooks fail silently. Always pair the two settings, or the URL convention quietly breaks server integrations.

  • Supabase service role needs explicit GRANT even with RLS disabled. 2026-05-09

    Disabling row-level security does not grant table access. Backend writes fail with permission errors until grant all on table … to service_role; is added in every table-creation migration.

  • Container queries for proportional SVG lockups. 2026-04-26

    SVG headline lockups that scale with their column (not the viewport) want container-type: inline-size on the parent + cqi sizing on the SVG. Viewport units break at intermediate widths when the column is narrower than the viewport.

Every shipped project adds entries here. The next project starts with these already loaded.

4C Quality system ▾

Quality is systematic, not subjective. The Evaluator grades every sprint against four criteria. Two are required passes — sprints cannot ship with failures there. The four approval gates in the workflow protect the system from drift.

The four criteria:

  • Originality Highest weight

    Evidence of deliberate creative decisions. No AI-default patterns. A human designer should see intent.

  • Design quality Highest weight

    Coherent whole. Color, type, layout, imagery, and interaction combine into a distinct mood, not a collection of parts.

  • Craft Required pass

    Typography hierarchy, spacing consistency, color harmony, contrast ratios. The competence floor. Failures here are disqualifying.

  • Functionality Required pass

    Users understand what the interface does, find primary actions, and complete tasks without guessing.

4D Creative defaults ▾

These are the defaults I've encoded so every session starts with a point of view, not a blank canvas. From studio-memory.md §9.

  • Start monochromatic.

    One accent, introduced late, with purpose. Three colors is usually one too many.

  • Springs over curves.

    Springs feel physical; cubic-beziers feel digital. Use springs unless the motion is choreographed on a timeline.

  • One typeface family, full range.

    Two families only if they refuse to compete. Display vs. body, sharp hierarchy, no overlap.

  • Grid as premise, not prison.

    Break the grid rarely and with force. The break works only because the grid exists.

  • Know the register.

    Dense UIs read as capable. Sparse UIs read as premium. Pick deliberately. Do not default to sparse because it is easier.

  • Detail is the craft, not the polish.

    Scrollbar, favicon, empty state, 404, loading skeleton, form-error copy. These are the work, not the finishing touches.

  • Copy ships, never lorem.

    Button labels, error copy, placeholders, onboarding. All design decisions. Production text is written, never filler.

Knowledge work surface

Cowork is the third tab. Not Code. Not Agent View.

Cowork is not Agent View. Agent View is the CLI multi-session control plane inside Claude Code. Cowork is the Desktop app's knowledge-work tab. They do not overlap.

06 :: For Hiring Managers

How I'd apply this at your company.

Pick your company size. The card answers what I would build first and what changes about how your design team operates. No hedging.

I am the design team.

  • This system is how one designer ships at the pace of three.
  • Studio memory means day-one context on your product, users, and patterns. No ramp-up amnesia between sprints.
  • The Planner turns a founder's rough brief into a structured spec in one session. No weeks of requirements gathering.
  • The Evaluator catches quality issues before they reach stakeholders. Design review without the headcount.
  • Tooling cost: ~$120/mo. The ROI is output velocity with zero quality compromise.

What I'd build first A WORKSPACE.md for your product, a studio-memory.md for your design patterns, and a sprint workflow tuned to your ship cadence.

I lead a design team.

  • This system is how I multiply their output without multiplying headcount.
  • Studio memory becomes the team's shared design intelligence. Onboarding accelerates, decisions compound, institutional knowledge survives turnover.
  • The Planner-Generator-Evaluator loop standardizes quality without standardizing creativity. Every designer still owns their craft. The system owns the consistency.
  • Sprint contracts and approval gates create the accountability structure design teams at this stage need, without adding process overhead.
  • The token strategy translates to a team budget: Sonnet for the volume work, Opus for the judgment work, Claude Design as a free creative resource on its own clock.

What I'd build first A design quality framework, a team-wide memory system, and an AI-assisted sprint workflow that integrates with your existing engineering cadence.

I lead a design function.

  • This system is the governance model that scales craft across business units without creating a bureaucracy.
  • Studio memory at this scale is a design knowledge graph. Principles, patterns, component decisions, and accumulated learnings any team in the org can query.
  • The agent architecture maps to enterprise roles: Planner is strategic design, Generator is the production team, Evaluator is the design quality function. AI makes each layer faster without collapsing the separation of concerns.
  • Approval gates align naturally with enterprise review cadences. Design review, accessibility audit, brand compliance, legal. No new sequential bottlenecks.
  • The token model translates directly to enterprise AI budgeting. Right-size the model to the task. Preserve capacity for high-judgment work.

What I'd build first A pilot with one product team. Prove the model. Measure velocity, quality scores, and designer satisfaction. Then scale with a governance framework that gives teams autonomy within guardrails.
